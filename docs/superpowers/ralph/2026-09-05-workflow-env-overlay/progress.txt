## Codebase Patterns

### Defensive raw ENV patch-key rejection
- **Where**: `packages/workflows/src/env-overlay.ts` (`assertRawPatchKeys` before `copyNodePatch`)
- **Pattern**: Zod `.strict()` is not enough for apply — callers can bypass the schema boundary. Inspect `Object.keys(rawPatch)` against `ENV_OVERLAY_PATCH_FIELDS` *before* `copyNodePatch()` strips unknowns; fail `forbidden_field` with field name only (never values/bodies). Detached normalized copy still feeds assignment + applied/snapshot.
- **Example**: `{ model: 'x', typo: 'secret-value' }` → `forbidden_field` field=`typo`; message excludes `secret-value`

### ENV editor body presence flags
- **Where**: `packages/web/src/experiments/console/lib/workflow-env-editor.ts` (`NodePatchDraft.promptEnabled`/`bashEnabled`)
- **Pattern**: Omission ≠ empty string. Enabled flag includes body byte-for-byte (including `''`/whitespace); disabled omits the key. Zero drafts → valid no-op `{}`; non-empty-per-chosen-node still enforced when rows exist.
- **Example**: `draft({ nodeId: 'plan', promptEnabled: true, prompt: '' })` → `{ plan: { prompt: '' } }`


### Symbol-preserving node clone
- **Where**: `packages/workflows/src/include-expander.ts` (`cloneNodeWithEngineMetadata`)
- **Pattern**: `structuredClone` drops symbol keys. Re-attach `COMPOSED_NODE` and nested `COMPILED_LOOP_COMMAND` (including loop_group body recursion) after clone. Shared by include expansion and ENV overlay — do not duplicate the private symbol list.
- **Example**: `cloneNodeWithEngineMetadata(node)` / `cloneWorkflowWithEngineMetadata(workflow)`

### ENV overlay field matrix
- **Where**: `packages/workflows/src/env-overlay.ts`
- **Pattern**: Allowed fields follow executor behavior, not the broad base Zod object: prompt→prompt/provider/model/effort/thinking; command→provider/model/effort/thinking; loop→provider/model/effort; loop_group→provider/model; bash→bash; other→none. Missing top-level ids skip; incompatible existing ids fail closed with safe codes (no prompt/bash bodies in errors).
- **Example**: `applyEnvOverlay(workflow, patches)` → `{ workflow, appliedPatches, missingNodeIds }`

### Empty prompt/bash vs dagNodeSchema
- **Where**: `packages/workflows/src/schemas/dag-node.ts` mode detection + `env-overlay.ts` `isEmptyBodyOnlyFailure`
- **Pattern**: `dagNodeSchema` treats whitespace-only prompt/bash as modeCount 0 and rejects. ENV contracts still allow empty/whitespace bodies byte-for-byte — after assign, accept only those known empty-body issues; other schema failures stay `invalid_patched_node`.
- **Example**: empty bash apply succeeds; malformed effort still fails

### Zod overlay schema conventions
- **Where**: `packages/workflows/src/schemas/env-overlay.ts`
- **Pattern**: Import `z` from `@hono/zod-openapi`; `z.infer`; explicit `z.record(keySchema, valueSchema)`; `.strict()` documents; stored overlay union tries complete snapshot before pending applied form.
- **Example**: `storedEnvOverlaySchema = z.union([envOverlaySnapshotSchema, appliedEnvOverlaySchema])`

### Shared NodeExecutionMetadata resolution
- **Where**: `packages/workflows/src/node-model-resolution.ts`
- **Pattern**: `resolveNodeExecutionRequest` is the pure chain + capability-aware effort/thinking used by `resolveNodeProviderAndModel`, `node_started`, ENV preview, and ENV snapshot. Callers MUST pass full `ResolveNodeExecutionOptions` (`aiProfile`, `assistants` for legacy `modelReasoningEffort`, `workflowThinking`) — never `{ aiProfile }` alone. `buildResolvedRequestMetadata` walks prompt/command/loop + nested group bodies with qualified ids (`group.child`); excludes group containers and deterministic nodes. `resolveGroupModelScope` forwards group provider/model/preset/tier while preserving outer effort. Explicit node/workflow portable effort fails without `effortControl`; preset-only effort drops via `presetEffortDropped` + `presetEffortRejection` (dag-executor logs that structured decision — never re-call `resolvePresetEffort`).
- **Example**: `request.metadata` === `node_started.data` request fields; body scope = `resolveGroupModelScope(group, outerScope, …)`; OpenCode tier `effort: high` → `presetEffortDropped: true`

### Workflow ENV store boundaries
- **Where**: `packages/core/src/db/workflow-envs.ts`
- **Pattern**: Normalize PG JSONB objects and SQLite JSON strings through `envPatchesSchema` before row parse. Corrupt rows throw `WorkflowEnvCorruptRowError` with id-only logs (never patch bodies). Name conflicts map only when PG `constraint === 'uq_workflow_envs_workflow_name_name'` or SQLite UNIQUE message names both identity columns. Update/delete always dual-predicate `(id, workflow_name)`; patches whole-document replace; empty `{}` allowed; empty update body rejected. List omits patches and orders `LOWER(name), name, id`.
- **Example**: `updateWorkflowEnv(wf, id, { patches: {} })` clears the map; mismatched workflow returns null without mutating.

### Atomic run envOverlay replacement
- **Where**: `packages/workflows/src/store.ts` (`IWorkflowEnvOverlayStore`), `packages/core/src/db/workflows.ts` (`setWorkflowRunEnvOverlay`)
- **Pattern**: Do not use `updateWorkflowRun` / `json_patch` for nested overlay writes — SQLite deep-merges and stale `resolved` keys survive. Replace only `metadata.envOverlay` via PG `jsonb_set(..., '{envOverlay}', $1::jsonb, true)` or SQLite `json_set(..., '$.envOverlay', json($1))`; UPDATE then SELECT in one transaction; no SQLite RETURNING; rowCount !== 1 throws.
- **Example**: `store.setWorkflowRunEnvOverlay(runId, completeSnapshot)` → full run row with siblings preserved

### Executor overlay ownership
- **Where**: `packages/workflows/src/executor.ts` (`prepareExecutionEnvOverlay`, complete snapshot before `workflow_started`)
- **Pattern**: Caller-supplied `appliedEnvOverlay` → verify only (workflow already patched). Else parse `preCreatedRun.metadata.envOverlay` and reapply frozen patches. Overlay-bearing preCreated runs use `preCreatedRun.user_id` for prefs/creds; no-overlay keeps `opts.userId`. Pending applied form is stamped at first INSERT; complete snapshot with live `resolved` is written via `setWorkflowRunEnvOverlay` before any start event/DAG using the same options as runtime (`aiProfile` + `config.assistants` + `workflow.thinking`). Audit/prepare failure: fail-closed, no execution. Fresh children never copy parent overlay.
- **Example**: `executeWorkflow(..., { appliedEnvOverlay })` or resume with `preCreatedRun.metadata.envOverlay` only

### Orchestrator pre-isolation ENV gate
- **Where**: `packages/core/src/orchestrator/env-overlay-dispatch.ts`, `orchestrator-agent.ts` (`dispatchOrchestratorWorkflow`)
- **Pattern**: Frozen `EnvOverlayCandidate` rides out-of-band. Fresh starts call `resolveFreshDispatchEnvOverlay` before isolation. Genuine continuations call only `resolveContinuationDispatchEnvOverlay` (request candidate never validated/applied). When a request candidate is present on a would-be continuation, hydrate early before isolation: real resume → stored/YAML + ignored-ENV notice; hydrate-null → validate request candidate pre-isolation (fail closed). Reuse early hydrate result (CAS must not run twice). Logs/messages: env id/name/codes only — never prompt/bash bodies.
- **Example**: incompatible request on paused run → resume stored ENV + notice; hydrate-null + incompatible → reject before isolation

### HTTP Workflow ENV CRUD + preview
- **Where**: `packages/server/src/routes/api.ts`, `packages/server/src/routes/schemas/workflow-env.schemas.ts`, `packages/workflows/src/env-overlay.ts` (`listEnvOverlayTargets`)
- **Pattern**: OpenAPI CRUD under `/api/workflows/{name}/envs` with camelCase wire mapper; list omits patches; create provenance via soft `resolveWebUserId` (null OK). Preview is a separate `/env-preview` route requiring `validateCwd`, discover+`resolveWorkflowName`, optional ENV identity (`400 env_not_found` / `env_workflow_mismatch`), `listEnvOverlayTargets` for editor matrix (top-level only), `applyEnvOverlay` + executor-parity `buildResolvedRequestMetadata` with full options (`aiProfile`, `config.assistants`, `workingWorkflow.thinking`) / `buildAiProfile` (corrupt prefs → config-only). Never echo prompt/bash in errors/responses.
- **Example**: `GET .../env-preview?cwd=...&envId=...` → `{ preview:true, authoritative:false, targets, resolved, skippedNodeIds }`

### Start route ENV freeze
- **Where**: `packages/server/src/routes/api.ts` (`POST /api/workflows/{name}/run`)
- **Pattern**: Parse optional `envId` (JSON string or multipart plain field; empty/omitted = YAML-only; array/non-string = 400 request-shape). Load unscoped row after field parse and BEFORE file/message persistence. Missing → `400 env_not_found`; `row.workflow_name !==` decoded route name → `400 env_workflow_mismatch`; corrupt → `500 env_store_corrupt`. Re-parse `structuredClone(row.patches)` via `envPatchesSchema` into a new tree, `Object.freeze` candidate `{ envId, envName, workflowName, patches }`, pass as `HandleMessageContext.envOverlay`. Do not discover/apply YAML on Start.
- **Example**: `extraContext.envOverlay` → orchestrator US-006 gate

### Console Start ENV picker + race-safe preview
- **Where**: `packages/web/src/experiments/console/skills/workflowEnvs.ts`, `store/keys.ts`, `lib/draft-env.ts`, `components/DraftRunCard.tsx`
- **Pattern**: Types from `@/lib/api.generated` only. Cache keys encode cwd/workflow/envId (`none` sentinel) so `useEntity` cannot apply a stale preview to a newer selection. `startRun` omits empty `envId` on JSON and multipart. None/YAML Start stays usable on list failure; selected ENV blocks Start while preview loading/error — never silent reset to YAML. Workflow change clears ENV + inputs synchronously (picker onChange + effect).
- **Example**: `K.workflowEnvPreview(cwd, name, envId)` → `skill.previewWorkflowEnv`; `isStartBlockedBySelectedEnv({ selectedEnvId, preview, previewError })`

### Console ENV manage dialog
- **Where**: `packages/web/src/experiments/console/components/WorkflowEnvManageDialog.tsx`, `lib/workflow-env-editor.ts`
- **Pattern**: Visual shell like EnvVarsDialog. Baseline `previewWorkflowEnv(wf, cwd, null)` supplies `targets`/`allowedFields` — never hardcode the node matrix. Summary list has no patches; `getWorkflowEnv` only on Edit. Thinking UI: unset|adaptive|enabled(+budget)|disabled. `buildPatchesFromDrafts` requires non-empty per-node patch; PATCH sends the complete map. After create/update/delete call `invalidateWorkflowEnvCaches` → list key + `workflowEnvPreview` prefix + optional detail key. Plaintext notice for prompt/bash; loop-group body non-target copy. 409 via `formatWorkflowEnvActionError(HttpError)`.
- **Example**: `invalidateWorkflowEnvCaches(name, id)`; `NodePatchEditor` only renders `allowedFields`

### Console run-detail ENV overlay
- **Where**: `packages/web/src/experiments/console/primitives/run.ts` (`parseRunEnvOverlay`), `RunDetailHeader.tsx`, `WorkflowEnvResolvedTable.tsx`
- **Pattern**: Hand-parse `metadata.envOverlay` without `@archon/workflows`. Require non-empty `envId`/`envName`/`workflowName`; never surface patches/prompt/bash. Pending = no `resolved` key; complete = object map → sorted rows. Malformed → `null` (omit chip/table; rest of run usable). Caption distinguishes planned request settings from node events / provider final models. Preview table stays non-authoritative Start-only copy.
- **Example**: `toRun(raw).envOverlay` → chip `env: <name>` + `WorkflowEnvResolvedTable`
