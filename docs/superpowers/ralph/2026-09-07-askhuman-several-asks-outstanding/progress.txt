## Codebase Patterns

### sprint-status conflict overlay can be committed file content
- **Where**: `_bmad-output/implementation-artifacts/workflow-run-view-hitl/sprint-status.yaml`
- **Pattern**: The Read-tool conflict diagnostic (`⚠ 2 unresolved conflicts`, `conflict://N`) can live as trailing bytes in HEAD, not only as a live overlay. On-disk YAML already matched `@theirs` (`2026-09-07 01:23:49 +0700` from `c25ea00c`). Rewrite the file without the diagnostic, then mark the story `done` with a fresh timestamp.
- **Gotcha**: `conflict://*` writes fail across turns (ids expire). `conflict://*` via Cursor Write becomes `conflict://*:raw` and is rejected. Verify markers with Python on file bytes, not workspace `rg` (it can see the overlay).

### Run-detail route tests are ESLint-ignored
- **Where**: `packages/server/src/routes/api.workflow-runs.test.ts` `describe('GET /api/workflows/runs/:runId')`
- **Pattern**: Append multi-row Ask characterizations after the last single-pending projection test (`projects awaiting from a pending row...`). The route test proves the server supplies all rows to the projector and returns them unchanged (timestamp serialization aside); do not recompute `isAwaitingInput` in the test.
- **Gotcha**: ESLint ignores this file; local gate is `prettier --check` plus `cd packages/server && bun test src/routes/api.workflow-runs.test.ts`. `NOW` and `MOCK_RUNNING_RUN` already exist in the file.

### InMemoryStore Ask-only pause omits approval metadata
- **Where**: `packages/workflows/src/subrun.test.ts` `InMemoryStore.pauseWorkflowRun`
- **Pattern**: Write `metadata.approval` only when `approvalContext !== undefined`. Spreading `undefined` as `{ ...approvalContext, resolved: null }` yields `{ resolved: null }`, which is not `undefined` and diverges from production SQLite.
- **Example**: `if (approvalContext !== undefined) { r.metadata = { ...r.metadata, approval: { ...approvalContext, resolved: null }, ...(extraMetadata ?? {}) }; }`
- **Gotcha**: Child Ask e2e depends on this parity — otherwise the child run looks like an approval gate. `subrun.test.ts` MUST run in its own `bun test` process (package.json already isolates it).

### AskHuman persist-and-pause lives in the native tool
- **Where**: `packages/workflows/src/ask-human.ts` after `insertPendingInteraction`
- **Pattern**: Each AskHuman call persists a pending row, then `pauseWorkflowRun(runId)` with no approval context, then throws `AskHumanAwaitingError`. Already-paused is idempotent. Same-node concurrent Asks therefore pause twice; the executor `pauseOnAskHuman` only records node `awaiting` and emits `node_awaiting`.
- **Gotcha**: Same-node two-Ask characterization fails if pause stays only in the executor catch (one unwind → one pause). Do not run `ask-human.test.ts` in the same `bun test` process as `dag-executor.test.ts` (`mock.module('@archon/paths')` pollution).

### Pending-interaction tests are a dedicated bun test segment
- **Where**: `packages/core/src/db/workflow-pending-interactions.test.ts`
- **Pattern**: File mocks `./connection` at module scope, so it MUST run as `cd packages/core && bun test src/db/workflow-pending-interactions.test.ts` in its own process. ESLint ignores it; gate is prettier + that focused test.
- **Helpers**: `seedRun`, `pauseRun`, `resolveInput`, `mixedEnvelope`, `runStatus` already exist; append new `resolvePendingInteraction` cases after the sibling-interaction test.
- **Gotcha**: `StrReplace` on this file truncated it to ~300 lines; restore via `git checkout` and insert with a script if that happens again.

### Pending-row awaiting overlay is per-node
- **Where**: `packages/workflows/src/retry-state.ts:189-200`
- **Pattern**: `projectLatestEffectiveNodeStates(events, pending)` overlays `awaiting` only onto nodes that own a `status === 'pending'` row. Answered rows are skipped. Mixed answered+pending on one node stays `awaiting`. A sibling with only answered rows stays at its event-derived state (`running` after `node_started`).
- **Example**: Overlay loop is `for (const row of pending ?? []) { if (row.status !== 'pending') continue; ... state: 'awaiting' }` keyed by `row.node_id`.
- **Gotcha**: Characterization tests must omit `node_awaiting` events; otherwise they cannot prove the overlay is what keeps the node awaiting.

### Workflows tests import schemas that need workspace install
- **Where**: `packages/workflows/src/schemas/retry.ts` via `@hono/zod-openapi`
- **Pattern**: A fresh worktree has no `node_modules`. Run `bun install` from the repo root before `bun test`.
- **Example**: `cd packages/workflows && bun test src/retry-state.test.ts` failed with `Cannot find module '@hono/zod-openapi'` until install.
