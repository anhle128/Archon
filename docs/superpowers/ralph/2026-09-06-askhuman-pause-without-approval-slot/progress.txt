## Codebase Patterns

### NodeState is a projection superset of NodeOutput
- **Where**: `packages/workflows/src/schemas/workflow-run.ts`
- **Pattern**: `awaiting` is a projection-only node status. `nodeStateSchema` / `workflowStepStatusSchema` include it; `nodeOutputSchema` and `workflowRunStatusSchema` do not. The compile-time assertion is one-way: `NodeOutput['state'] extends NodeState`.
- **Example**: `type AssertNodeOutputStateIsNodeState = NodeOutput['state'] extends NodeState ? true : never;`

### Projector pending overlay
- **Where**: `packages/workflows/src/retry-state.ts` `projectLatestEffectiveNodeStates(events, pending?)`
- **Pattern**: `node_awaiting` sets `state: 'awaiting'` and preserves existing `output` (does not copy event output). `interaction_resolved` is a no-op. After events, each pending row with `status === 'pending'` forces that `node_id` to `awaiting`. Answered/purged rows do not overlay.
- **Example**: `projectLatestEffectiveNodeStates(events, [{ node_id: 'review', status: 'pending' }])`

### Widening NodeState requires API local union until US-006
- **Where**: `packages/server/src/routes/api.ts` `ApiWorkflowNodeState.status`
- **Pattern**: GET run maps `projected.state` onto a local status union. Until US-006 switches `workflowNodeStateSchema.status` to `nodeStateSchema`, that local union must include `awaiting` or `@archon/server` type-check fails.
