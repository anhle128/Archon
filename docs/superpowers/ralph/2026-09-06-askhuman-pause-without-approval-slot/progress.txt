## Codebase Patterns

### bun run validate lint needs extra Node heap locally
- **Where**: `package.json` `lint` (`bun x eslint . --cache --max-warnings 0`)
- **Pattern**: Default Node heap OOMs around 4 GB during full-repo eslint. Set `NODE_OPTIONS=--max-old-space-size=8192` so `bun run validate` can finish. `bun run check:schema-upgrades` uses `spawnSync('psql')`; bun's PATH may omit Homebrew `libpq` — copy the real `psql` binary onto a bun-visible PATH (e.g. `~/.bun/bin/psql`).
- **Example**: `NODE_OPTIONS=--max-old-space-size=8192 DATABASE_URL=postgresql://postgres:postgres@localhost:5432/remote_coding_agent bun run validate`

### CAP-7 AskHuman preflight is unconditional and scope-shared
- **Where**: `packages/workflows/src/dag-executor.ts` `collectAskHumanUnsupportedProviders`
- **Pattern**: Build one outer `WorkflowModelScope` at run start. Visit command/prompt/loop nodes and nested `loop_group` bodies with `resolveGroupModelScope` / `resolveNodeProviderForPreflight`. Match only `allowed_tools` after `entry.split('(')[0].trim()` against `AskHuman` and `mcp__archon__AskHuman`. Ignore `denied_tools`. If `askHuman === false`, throw before any `sendQuery`. Reuse the same scope for the containerExec preflight. Chat still injects only `manage_run`.
- **Example**: `AskHuman is not supported by provider 'codex'. Remove AskHuman from allowed_tools, or use claude or pi.`


### AskHuman injection is capability-gated and pauses without completing
- **Where**: `packages/workflows/src/ask-human.ts`, `packages/workflows/src/dag-executor.ts` `nativeToolsForAskHuman` / `pauseOnAskHuman`
- **Pattern**: Inject `[createAskHumanTool(...)]` only when `getProviderCapabilities(provider).askHuman` is true, on command/prompt `sendQuery` and loop iteration `sendQuery`. Catch `AskHumanAwaitingError` before abort/cancel classification; `pauseWorkflowRun(runId)` with no approval context; transcript `awaiting`; live `{ type: 'node_awaiting', runId, nodeId }`; return `{ state: 'completed', output }` with no `node_completed`/`node_failed`. Skip abort classification for `AskHumanNoStarterError` so provider abort cannot masquerade as cancel. Loop mocks that yield a `result` must keep the generator open (e.g. live `background_tasks`) or the executor breaks before the Ask throw.
- **Example**: `if (error instanceof AskHumanAwaitingError) { await pauseOnAskHuman(...); return { state: 'completed', output: nodeOutputText }; }`

### askHuman is a required ProviderCapabilities axis
- **Where**: `packages/providers/src/types.ts`, `scripts/generate-capability-matrix.ts` `AXES`
- **Pattern**: Add `askHuman: boolean` to the type, set it on every `*CAPABILITIES` object, and append `{ key: 'askHuman', label: 'AskHuman mid-turn questions' }` to `AXES`. Only Claude and Pi are `true`. A new field without an axis fails `bun run check:capability-matrix`. Do not use StrReplace/Edit on large `*.test.ts` files in this worktree — they truncate; patch with Python exact-string replace.
- **Example**: `expect(getProviderInfoList().filter(i => i.capabilities.askHuman).map(i => i.id).sort()).toEqual(['claude', 'pi']);`

### Pi AskHuman bridge is session-local
- **Where**: `packages/providers/src/community/pi/provider.ts` `sendQuery`
- **Pattern**: Mutable `askSessionRef` starts empty; assign `session` immediately after `createAgentSession`. Runtime `sessionId()` reads the first non-empty `session.sessionId`. `onControlError` stores the branded instance and `void session.abort()`. After `bridgeSession` returns or throws, rethrow the stored instance before success/failure classification so Pi's tool-error conversion cannot swallow Ask. Tests capture `defineTool` defs and invoke `execute` from `mockPrompt`, which catches the throw then still completes the prompt.
- **Example**: `if (askControlError) throw askControlError;`

### Claude AskHuman bridge is attempt-local
- **Where**: `packages/providers/src/claude/provider.ts` `sendQuery` attempt loop
- **Pattern**: Per-attempt `ClaudeAskBridge` stores first non-empty `session_id`, pending Ask `tool_use_id`, and branded `controlError`. Compose `PreToolUse` with matcher `mcp__archon__AskHuman` (do not invent ids). `contextFor('AskHuman')` consumes the captured id. `onControlError` stores the instance and `controller.abort()`. Throw `askBridge.controlError` before `classifyAndEnrichError` and after a clean iterator exit so abort/retry classification cannot swallow Ask. Provider tests must mock `tool()` + `createSdkMcpServer` and drive both abort-rejection and swallowed-callback SDK outcomes.
- **Example**: `if (askBridge.controlError) throw askBridge.controlError;`

### Native tool converter runtime is optional and identity-preserving
- **Where**: `packages/providers/src/claude/native-tools.ts`, `packages/providers/src/community/pi/native-tools.ts`
- **Pattern**: Recurse only for array-of-strings and array-of-objects; preserve `minItems`. `buildArchonMcpServer(tools, runtime?)` / `buildPiNativeToolDefinitions(tools, defineTool, runtime?)` stay optional so existing callers compile. Catch only `AskHumanAwaitingError` / `AskHumanNoStarterError` for `onControlError`, then rethrow the same instance. Pi always forwards `_toolCallId` as `toolUseId`; Claude context is supplied by Task 9 via `contextFor`. Claude tests mock `tool()` to capture the callback; Pi uses the existing `defineTool` seam. Lint production files only — `*.test.ts` is eslint-ignored.
- **Example**: `if (error instanceof AskHumanAwaitingError || error instanceof AskHumanNoStarterError) { runtime?.onControlError(error); } throw error;`

### node_awaiting SSE is status-only refetch
- **Where**: `packages/server/src/adapters/web/workflow-bridge.ts`, `packages/workflows/src/event-emitter.ts`
- **Pattern**: Do not put `node_awaiting` in `ROW_WORKFLOW_STATUS` (that map cannot express `paused`). Special-case it beside `approval_requested` in both `mapWorkflowEventRow` and `mapWorkflowEvent`. Emit `workflow_status` with `status: 'paused'` and omit `approval` / `envelope` / `questions`. Add the type to `DASHBOARD_SOURCE_EVENT_TYPES` so the poller sees it. Do not map `interaction_resolved` in Story 6.2. Slack's exhaustive `WorkflowEmitterEvent` switch needs a no-op `case 'node_awaiting'` so it does not steal the approval card.
- **Example**: `case 'node_awaiting': return JSON.stringify({ type: 'workflow_status', runId, workflowName: '', status: 'paused', timestamp })`


### GET run embeds pending rows and projects awaiting
- **Where**: `packages/server/src/routes/api.ts`, `packages/server/src/routes/schemas/workflow.schemas.ts`
- **Pattern**: `GET /api/workflows/runs/:runId` calls `listPendingInteractions(runId)`, maps `created_at`/`resolved_at` through `toISOString`, returns that array as `pending_interactions`, and passes `{ node_id, status }` into `projectLatestEffectiveNodeStates`. `workflowNodeStateSchema.status` is `nodeStateSchema`, not a local enum. `settleApiWorkflowNodeStatesForRunStatus` still only rewrites `running` on terminal runs, so paused+awaiting stays awaiting. Node transcript messages stay a direct `listNodeMessages` map — never mix in pending envelopes.
- **Example**: `projectApiWorkflowNodeStates(events, pendingInteractions)`

### Store capability composition
- **Where**: `packages/workflows/src/store.ts`, `packages/core/src/workflows/store-adapter.ts`
- **Pattern**: Add a narrow store interface (`IWorkflowPendingInteractionStore`) and compose it into `IWorkflowStore` beside `IWorkflowNodeMessageStore`. Adapter methods are direct DB pass-throughs with no parsing or policy. Typed doubles get stub methods; `subrun.test.ts` `InMemoryStore` stores rows in an array and lists by run id.
- **Example**: `insertPendingInteraction: input => workflowPendingInteractionDb.insertPendingInteraction(input)`

### Pending insert is getDatabase().withTransaction, not pool
- **Where**: `packages/core/src/db/workflow-pending-interactions.ts`
- **Pattern**: Production `pool` is query-only. Parse `insertPendingInteractionSchema` before opening `getDatabase().withTransaction`, then use only the transaction-scoped `query` for the run lock, pending INSERT, `insertWorkflowEvent`, and canonical SELECT. Build `FOR UPDATE` locally (`getDatabaseType() === 'postgresql' ? ' FOR UPDATE' : ''`); do not import private `rowLockClause()`.
- **Example**: `const parsed = insertPendingInteractionSchema.parse(input); return getDatabase().withTransaction(async query => { ... })`

### mock.module('./connection') tests need their own bun test shard
- **Where**: `packages/core/package.json` `test` script
- **Pattern**: Own invocation immediately after `workflow-node-messages.test.ts`. The in-memory SqliteAdapter is passed as `pool`, `getDatabase`, `getDialect`, and `getDatabaseType: 'sqlite'`.
- **Example**: `&& bun test src/db/workflow-pending-interactions.test.ts`

### New tables are CREATE TABLE only, comments split
- **Where**: `migrations/000_combined.sql`, `packages/core/src/db/adapters/sqlite.ts` `createSchema`
- **Pattern**: Add the table after the previous application table and before `-- Indexes and column comments`. Keep `COMMENT ON TABLE` beside CREATE TABLE. Put every `COMMENT ON COLUMN` in the trailing section. Do not add `CREATE INDEX` when a named UNIQUE constraint is the covering lookup. Do not add a brand-new table to `migrateColumns` — `CREATE TABLE IF NOT EXISTS` creates it on existing databases.
- **Example**: `CONSTRAINT uq_pending_interactions_run_tool_use UNIQUE (workflow_run_id, tool_use_id)`


### Ask pause leaves metadata.approval untouched
- **Where**: `packages/core/src/db/workflows.ts` `pauseWorkflowRun`
- **Pattern**: `approvalContext === undefined` runs a status-only UPDATE (`WHERE status = 'running'`). Zero-row match succeeds only if current status is already `paused`; otherwise throws the existing not-running error. Gate pause (context provided) still json-merges `metadata.approval` with explicit-null subfields and has no paused fallback. `extraMetadata` is ignored on the Ask path.
- **Example**: `await pauseWorkflowRun(runId)` // Ask; `await pauseWorkflowRun(runId, approvalContext)` // gate

### NodeState is a projection superset of NodeOutput
- **Where**: `packages/workflows/src/schemas/workflow-run.ts`
- **Pattern**: `awaiting` is a projection-only node status. `nodeStateSchema` / `workflowStepStatusSchema` include it; `nodeOutputSchema` and `workflowRunStatusSchema` do not. The compile-time assertion is one-way: `NodeOutput['state'] extends NodeState`.
- **Example**: `type AssertNodeOutputStateIsNodeState = NodeOutput['state'] extends NodeState ? true : never;`

### Projector pending overlay
- **Where**: `packages/workflows/src/retry-state.ts` `projectLatestEffectiveNodeStates(events, pending?)`
- **Pattern**: `node_awaiting` sets `state: 'awaiting'` and preserves existing `output` (does not copy event output). `interaction_resolved` is a no-op. After events, each pending row with `status === 'pending'` forces that `node_id` to `awaiting`. Answered/purged rows do not overlay.
- **Example**: `projectLatestEffectiveNodeStates(events, [{ node_id: 'review', status: 'pending' }])`

### Widening NodeState requires API local union until US-006
- **Where**: `packages/server/src/routes/api.ts` `ApiWorkflowNodeState.status`
- **Pattern**: GET run maps `projected.state` onto a local status union. Until US-006 switches `workflowNodeStateSchema.status` to `nodeStateSchema`, that local union must include `awaiting` or `@archon/server` type-check fails.
