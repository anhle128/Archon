## Codebase Patterns

### Ask submit keys on tool_use_id
- **Where**: `packages/web/src/components/workflows/NodeTranscriptPane.tsx`, `packages/server/src/routes/api.ts` `resolvePendingInteraction`
- **Pattern**: Card submit/decline must call `onSubmitAsk(interaction.tool_use_id, body)`. The server resolves pending Asks by `tool_use_id`, not `interaction.id`. `emptyAskActionStates` is a factory — pass it as the `useState` lazy initializer (`useState(emptyAskActionStates)`), not `useState(emptyAskActionStates())`. Named read-only Ask forms use a disabled `fieldset`; happy-dom does not propagate `fieldset.disabled` to `input.disabled`. Transcript query key is `[runId, nodeId]`, so fixtures that share those ids must `queryClient.clear()` between cases. Loop-slice isolation needs a post-loop message; the default FIXTURE iter-2 row is at the transcript tail.
- **Example**: `void onSubmitAsk(interaction.tool_use_id, body);`

### Real queryClient invalidation spies
- **Where**: `packages/web/src/stores/workflow-store.ts`, `packages/web/src/stores/workflow-store.test.ts`
- **Pattern**: `handleWorkflowStatus` invalidates via `invalidateWorkflowQueries()` when status is `running`, `paused`, or terminal. Tests spy on the real imported `queryClient.invalidateQueries`, assert `{ queryKey: ['workflowRun'] }` with `toHaveBeenCalledWith`, and `mockRestore` in `afterEach`. Do not `mock.module` the query client.
- **Example**: `spyOn(queryClient, 'invalidateQueries').mockResolvedValue(undefined);`

### Awaiting vs CAP-7 chrome
- **Where**: `packages/web/src/components/workflows/awaiting-chrome.ts`, `WorkflowAskChrome.tsx`
- **Pattern**: Count only `kind === 'ask' && status === 'pending'`. Awaiting is `paused` plus count > 0. CAP-7 is `startsWith('AskHuman is not supported by provider')`. `nodeStatusLabel` rewrites only `awaiting` to `waiting on you`. Chrome is mutually exclusive: failed + CAP-7 renders an error banner and no pill; otherwise the warning pill. Pill click calls `onRequestGraphView` then `onSelectAwaitingNode`; both are no-ops when `firstAwaitingNodeId` is null. Native `<button>` lets tests invoke the function component and fire `onClick` without happy-dom. React 19 test `ReactElement.props` is `unknown` — read `className` through a typed helper.
- **Example**: `if (nodeId === null) { return; }`

### In-tree Ask decline dialog
- **Where**: `packages/web/src/components/workflows/AskCard.tsx`
- **Pattern**: Keep Other-selected flags and Other text in separate state so custom text equal to a listed option cannot move the checked indicator. Project an empty-string sentinel while Other text is empty so `isAskDraftValid` keeps Submit disabled. Decline confirmation is an in-tree `role="alertdialog"` using `Button`; Radix `AlertDialogContent` portals and does not mount under this package's happy-dom harness even when `onClick` fires. Tests drive controlled inputs through the fiber `__reactProps$` onChange, matching `WorkflowEnvManageDialog.test.tsx`.
- **Example**: `const isOtherOn = otherSelected[question.id] ?? false;`

### Independent Ask action vs presentation
- **Where**: `packages/web/src/components/workflows/ask-answer-controller.ts`, `packages/web/src/components/workflows/ask-card-presentation.ts`
- **Pattern**: Inject `postAnswer`, `setActionState`, `invalidate`, and `now`. Own a private `Set<string>` for in-flight ids; add before POST and delete in `finally` after invalidation. Duplicate in-flight submits return without a second POST. Emit `sending` then `accepted` / `rejected-late` (HTTP 409 via `getApiErrorStatus`) / `error` (`Error.message` or `Failed to answer.`). Success and 409 invalidate; catch invalidation with `console.warn('[AskAnswer] Failed to invalidate query cache', { runId, requestId, error })` and keep the terminal local state. Presentation precedence: `rejected-late` over canonical, then `sending`, then `parseAskAnswer(interaction.answer)` over local `accepted`, then local error, then pending. `failed-resume` requires an effective answer plus `nodeStatus === 'failed'` and `nodeError.startsWith('Could not resume the AskHuman session')`. Malformed canonical payloads set `error: 'Malformed canonical answer'` and stay `answered` without throwing.
- **Example**: `if (inFlight.has(requestId)) { return; }`

### Loop-safe Ask placement
- **Where**: `packages/web/src/components/workflows/merge-agent-room-items.ts`
- **Pattern**: Filter `kind === 'ask'` + node + `pending|answered` in GET order. An Ask is anchored when `tool_use_id` matches a tool message `payload.id` in the full transcript and is kept only if that tool id is also in `visibleMessages`. Unanchored Asks are kept only when the last visible message id equals the sorted full-transcript tail. Merge sorts by `seq`, places matching cards immediately after the tool row, and appends leftover selected rows once using `ask:${interaction.id}`.
- **Example**: `return visible[visible.length - 1].id === full[full.length - 1].id;`

### NodeRoom generic slots need a runtime Fragment import
- **Where**: `packages/web/src/components/workflows/NodeRoom.tsx`
- **Pattern**: `NodeRoom.tsx` otherwise uses `React.*` only as erased types. Keyed `React.Fragment` is a runtime value and throws `React is not defined` under `NODE_ENV=development` `renderToStaticMarkup`. Import `{ Fragment } from 'react'` and key it with `message.id` so each message stays adjacent to `renderAfterMessage`. Loading suppresses both slots; empty transcripts replace the placeholder with `renderAtEnd`; error renders Retry then `renderAtEnd`.
- **Example**: `import { Fragment } from 'react';`

### Ask envelope parser rejects extra keys
- **Where**: `packages/web/src/components/workflows/parse-ask-envelope.ts`
- **Pattern**: Pure TypeScript type guards, no Zod or `@archon/workflows`. Reuse one `isPlainObject` helper (object, not null, not array). Strict answer decoding matches the canonical Zod `.strict()` union by requiring exact own keys via `Object.keys` length plus membership. Duplicate question IDs are tracked in a local `Set<string>` and fail the whole envelope. Draft Other values must be trimmed non-empty and are only legal when `allowOther` is true; listed options match exactly without trimming.
- **Example**: `return keys.length === allowed.length && allowed.every((key) => keys.includes(key));`

### Typed Ask answer client
- **Where**: `packages/web/src/lib/api.ts` beside `getWorkflowRun`
- **Pattern**: Export generated schema types, wrap the existing `fetchJSON` helper once with `encodeURIComponent` path params, and extract HTTP status via `typeof === 'object'`, a null guard, the `in` operator, and `typeof status === 'number'` — never `any` assertions. Client tests spy on `globalThis.fetch` and assign `window.location.origin` because `assertApiResponseOk` builds `new URL(url, window.location.origin)` on non-2xx.
- **Example**: `return typeof status === 'number' ? status : null;`

### GET-run viewer presentation
- **Where**: `packages/server/src/routes/api.ts` GET `/api/workflows/runs/:runId`; schema in `packages/server/src/routes/schemas/workflow.schemas.ts`
- **Pattern**: Compute `viewer_is_starter` from `resolveAuthContext(c)` vs `run.user_id` (never a Better Auth session id). Look up `starter_display_name` with `userDb.getUserById` only when `run.user_id` is non-null; trim `display_name` and fall back to `run.user_id`. Starter-less runs return `false` and `null` with no lookup.
- **Example**: `const starterDisplayName = starter?.display_name?.trim() || run.user_id;`

### mock.module users factory must stub getUserById
- **Where**: `packages/server/src/routes/api.workflow-runs.test.ts`
- **Pattern**: `mock.module()` merges; an omitted export keeps the real implementation. Calling `userDb.getUserById` without adding it to the users factory opens a real DB. Stub `getUserById` next to `findOrCreateUserByPlatformIdentity` and reset it in the GET-run `beforeEach`.
