# Node Transcript From Logs (Legacy)

## Overview

Implement Story 5.1 from the workflow-run view HITL work: an operator can select an unmerged node-run row in the legacy Logs tab and inspect that agent node's durable, chronological transcript while a workflow is running and after it has finished. The source plan is docs/superpowers/plans/2026-09-06-node-transcript-logs-legacy.md and the linked issue is #81.

The solution is a deliberately narrow vertical slice: immutable per-node message rows are persisted through a two-method workflow-store port; command, prompt, and loop agent execution append ordered text, tool-call, and lifecycle notes through an awaited fail-open helper; a nested read route exposes only that transcript; and the legacy Logs tab gains a selectable node-run list and one room. Server-projected node states remain the only source of current lifecycle.

## Problem

The current legacy Logs tab reuses a merged WorkflowLogs panel, so it cannot replay the durable output of one node run. Workflow events contain useful historical loop and route-loop metadata but cannot safely reconstruct current node lifecycle. There is also no durable per-node transcript storage or API contract.

## Goals and success metrics

- Persist one immutable, sequenced transcript timeline per workflow run and node, including text, tool calls, and status notes.
- Preserve provider chunk order: a non-empty assistant chunk is written before a later tool chunk even when platform batching delays display.
- Keep execution available when transcript persistence fails; log only safe metadata.
- Return 404 for a missing run, an ordered empty list for an existing run with no transcript, and no rows outside the requested run/node.
- Render chronological unmerged normal, loop-iteration, and route-loop rows in the legacy Logs tab, with exact marker-bounded loop transcript selection.
- Poll node transcript data every second only while a run is pending or running.
- Pass all targeted tests, type checks, schema checks, full validation, and the PostgreSQL upgrade gate when configured; only then mark the Story 5.1 sprint status done.

## Data and behavior contract

Storage table remote_agent_workflow_node_messages has exactly id, workflow_run_id, node_id, seq, kind, payload, and created_at. It cascades with the run; seq is positive; kind is text, tool, or status; and UNIQUE(workflow_run_id, node_id, seq) is the lookup/order index. The store assigns a dialect id, JSON-stringifies payload, calculates MAX(seq)+1 in a transaction, and on only the adopted sequence unique conflict starts one fresh transaction and retries exactly once.

The canonical workflow schemas are strict discriminated unions. Text payload is non-empty text; tool payload is non-empty name and id plus optional input/output; status payload is non-empty state plus optional detail. Append input omits id, seq, and created_at. PendingInteraction has the adopted Ask/permission shape solely to type GET-run's required pending_interactions array, which is always empty in this story.

Command and prompt nodes append started after their scheduled node_started event; append each non-empty assistant chunk and tool call in provider order; and append exactly one completed or failed terminal note after the corresponding scheduled lifecycle event. Loop nodes use the same lifecycle rows plus iteration_started, iteration_completed, and iteration_failed notes whose detail is the decimal iteration. Loop assistant text is completion-tag-stripped and omitted if empty. Only command, prompt, and loop paths record; bash, script, workflow, approval, plannotator_gate, route_loop, and loop_group container output do not.

The messages endpoint is GET /api/workflows/runs/{runId}/nodes/{nodeId}/messages. It checks that the run exists before reading, returns a strict messages array in ascending seq order, excludes workflow_run_id and node_id from the wire rows, and returns a fixed safe 500 error. GET /api/workflows/runs/{runId} keeps projectLatestEffectiveNodeStates via projectApiWorkflowNodeStates and adds pending_interactions: [] without a pending-table read.

Legacy log rows use server nodeStates for normal-row status. Loop events replace a node's base row with iteration rows; route events replace it with route execution rows. Event position orders all rows, with original nodeStates position as a stable tie-breaker. An ordinary re-executed node still has one latest row, placed by its latest node_started event; this is intentional until an execution identity is adopted. A selected loop iteration shows its matching iteration_started marker through its completed/failed marker; a missing start marker shows the full transcript.

## Delivery and validation rules

Follow test-driven development per story: introduce the stated focused failing tests, observe RED, add only the minimal production behavior, observe GREEN, and refactor only with green tests. Do not run bun test from the repository root. Use package-directory tests and package type checks; mock.module tests must be isolated in their package scripts. Regenerate the bundled schema from the migration rather than editing it and regenerate web API types from a live isolated server, never by hand.

The final story runs the focused suites, bun run check:schema-upgrades when PostgreSQL is reachable, and bun run validate. It also performs the manual walkthrough: a command/prompt node with a tool call and a two-iteration loop show unmerged ordered rows; normal and marker-bounded loop transcripts replay after completion; empty transcripts use the exact copy; Graph retains its merged panel; and prohibited Ask/awaiting chrome is absent. Only after all automated and manual checks pass may development_status.5-1-open-a-nodes-own-transcript-from-logs-legacy change from backlog to done.
