- (direction) User's framing, verbatim intent: clicking a node of a RUNNING agent must stop being read-only review and become a place to work with that agent. The read-only transcript is a separate, already-finished contract.
- (direction) User specified the control model: while the node runs the send button reads Queue and messages wait; after Stop node the same button reads Send now and sending delivers the whole queue plus the newly typed message in written order, then the node resumes; when it resumes both controls revert automatically. Both follow NODE STATE, never a mode the reader must remember setting.
- (decision) The draft queue lives in browser state, by the user's explicit call — no table, no migration. Justified rather than assumed: the agent runs as a subprocess of the server, so a server death kills the run, and a persisted queue would have had nothing left to deliver to. The UI must say the queue is per-tab instead of letting the operator believe the server holds it.
- (capability) CAP-1 compose while the agent works — a message can be written without disturbing the running node.
- (capability) CAP-2 stop a running node from its own room — today only whole-run abandon exists; node-level stop does not.
- (capability) CAP-3 send the queue on resume — everything written is delivered in written order, then the node continues.
- (capability) CAP-4 the exchange is part of the record — the operator's messages and the interrupted tool call are ordinary transcript rows in the order they happened.
- (capability) CAP-5 mid-turn delivery where the provider allows it — no stop required, gated per provider and never assumed.
- (capability) CAP-6 the interface claims only what it knows — 'sent' until the provider echoes back the id we stamped, and only then 'delivered'.
- (constraint) THE BLOCKER IS OURS, NOT THE PROVIDERS'. IAgentProvider.sendQuery() is a one-shot async generator with no way to push a message in after it starts, and each provider keeps its child process private inside that closure. All five providers in use accept steering on their side; nothing in Archon can reach them. One steering seam on the provider interface, shared by all five.
- (constraint) STOP IS NOT UNDO. Session state is saved to the last completed tool call, but files the agent already wrote stay written — nothing is rolled back. Grok's own shipped docs state it, and Archon's existing abort path has always behaved this way. The control must not imply otherwise.
- (constraint) Delivery confirmation correlates by message id alone, never by matching text or timestamps.
- (constraint) A steer delivery must not emit a turn-start event — aion records that a stray one opens a phantom turn boundary mid-stream.
- (constraint) Provider support is a declared capability that defaults to UNSUPPORTED. An unproven provider is treated as incapable until shown otherwise, which is how aion gates the same feature.
- (constraint) omp — native steer in RPC mode, and steer is its DEFAULT streaming behaviour. Cheapest of the five: RPC emits the same event vocabulary the existing OmpEventParser already reads, wrapped in an envelope. TRAP recorded deliberately: use RPC mode, NEVER omp acp — ACP implicitly cancels a running turn when a new prompt arrives (acp-agent.ts:819-835), which looks like steering and behaves like a stop.
- (constraint) claude — streaming input plus interrupt(); interrupt() is documented as available ONLY in streaming input mode. Needs an SDK bump from the pinned 0.3.209 (latest 0.3.269; the pre-result echo needs 0.3.246). A caller-set uuid on the user message is echoed back as user_message_uuid, which is what turns 'sent' into 'delivered' — and the docs state a plain string prompt, which is what Archon passes today, carries none.
- (constraint) codex — JSON-RPC turn/steer, a soft injection queued into the active turn's input, explicitly NOT a hard cancel.
- (constraint) grok — SETTLED BY EXPERIMENT this session, not inference. x.ai/interject is NOT reachable by a third-party ACP client: over grok agent stdio it answers -32601 Method not found, byte-identical to the answer given to a method invented as a control. The reachable channel is the hooks extension the handshake DOES advertise — x.ai/hooks with blockingEvents including pre_tool_use and stopSignals including additionalContext, a text channel to the agent at each tool boundary. Advertised and reachable; the exact payload is read from the capability shape and wants one implementation spike.
- (constraint) deepseek — no native mid-turn, MEASURED: a second prompt is rejected in 2ms with -32602 'a prompt is already in flight for this session'. Warm cancel-and-continue on the same open connection measured at 31ms end to end, and the cancelled turn's partial output is RETAINED. The first turn costs about 3.6s of context assembly, so a cold stop-and-resume pays that again every time the operator speaks. Requires not closing the session and not reaping the child.
- (note) Convergence worth building on: three of the five deliver at the SAME point — the next tool-call boundary. omp checks steering between tool calls, grok blocks at pre_tool_use, claude's hook contract is the same shape. That is the natural rest point of an agent loop, so the seam should take 'deliver at the next boundary' as its default meaning and treat immediate interrupt as the special case, not the reverse.
- (decision) NON-GOAL: qodercli, pi, copilot and opencode. The user stated they do not use those harnesses today. Two of them were checked far enough to know they could join later.
- (decision) NON-GOAL: persisting the draft queue — see the browser-state decision and its justification.
- (decision) NON-GOAL: cancelling one individual tool call. No provider offers it: claude reports the command unsupported at that granularity and codex has nothing on the wire below turn level. Stopping is turn-level or session-level only.
- (decision) NON-GOAL: the read-only transcript itself. That is spec-readable-agent-transcript, already specced and reviewed, and it already renders the interrupted-tool outcome that a stop produces.
- (question) OPEN: what does the composer do on a FINISHED node — does a message re-run it, or is the composer simply absent? Not decided; deliberately left rather than invented.
- (question) OPEN: does deepseek's session/cancel interrupt a running TOOL CALL as cleanly as it interrupts a model stream? Only streaming was exercised.
- (question) OPEN: grok's hooks payload — the mechanism is advertised and reachable, but the exact additionalContext shape is inferred from the capability declaration and needs one live spike to confirm.
- (event) grok reachability question CLOSED by direct experiment: ACP initialize handshake plus three method probes over grok agent stdio, no model call, no cost, no orphaned process.

- (constraint) Pause in Archon is run-level, not node-level: pauseWorkflowRun(runId, approvalContext) at dag-executor.ts:6832; the node returns 'completed' and the between-layer status check halts the run (:6744, :6746). There is no suspended-in-place node.

- (question) Which lifecycle shape does 'stop a node' take: a new node state the executor respects, or run-level pause reusing the approval machinery with a synthetic context (the pattern container write-back already uses)? Undecided; blocks CAP-2 and CAP-3.
- (constraint) The executor is NOT always in the API server's process. Web dispatch imports and awaits executeWorkflow in-process (server/src/routes/api.ts:3200-3228); CLI --detach spawns a detached child in its own process group (cli/src/commands/workflow.ts:696-722). An in-memory steering registry therefore reaches in-process runs only.
- (decision) AskHuman does NOT prove a process-independent delivery path: listPendingInteractions (dag-executor.ts:10367) is a RESUME preflight read at run start, not a poll by a live executor. Pause ends the execution; resume re-enters. So the answer reaches a NEW execution, never a running one.
- (question) Is steering a detached run (CLI --detach, its own process) in scope, or is the feature scoped to runs the server itself executes? Scope decision, not a technical one.
- (constraint) Operator rows need an explicit speaker marker. workflow_node_messages carries kind text|tool|status with no speaker field (schemas/node-message.ts:39-43), and nodeTranscriptMetadataSchema is .strict() (schemas/node-execution.ts:29-43), so metadata is NOT free JSON: an origin field must be added to the schema. Additive, no DB migration (the column is JSON), but a typed contract change plus a regenerated api.generated for the web.
- (decision) Operator messages are stored as node transcript rows with metadata.origin='operator' rather than a new table or a widened kind enum. Reuses existing enum values, matching aion's own lesson (service.rs:3559-3568) and Archon's additive-only schema rule.
- (constraint) CROSS-SPEC: AgentHistoryItem in spec-readable-agent-transcript has kinds assistant|tool|lifecycle. An operator row is none of the three, so CAP-4 requires a new item kind and a row treatment on both shells in THAT spec. Logged as a dependency; that spec is not edited from here.
- (decision) Stale-steer guard: a steer carries node id plus retry epoch as optimistic concurrency, so a steer aimed at a superseded attempt is rejected rather than misdelivered. Shape taken from aion's expectedTurnId (codex_conn.rs:4043-4090, aion report section 5).
- (constraint) After a stop, do not call execute directly: wait for the runtime to report ready first, or hit the race aion named in AcpSendBox.tsx:771-775. The stop and the resume are two gated steps, never one call.
- (constraint) omp's steering queue defaults to one-at-a-time (steeringMode default, scoutcli report section 1.3), so delivering a whole queue in written order needs set_steering_mode 'all' or explicit per-item sequencing. CAP-3's ordering promise is not free.
- (constraint) omp RPC: send negotiate_protocol protocolVersion 2 immediately or stdout frames over 1 MiB are lossy (scoutcli report section 1.4).
- (decision) Codex row downgraded to unverified. turn/steer is aion's app-server JSON-RPC spoken directly (codex_conn.rs:4043-4090); Archon speaks @openai/codex-sdk 0.144.5 via thread.runStreamed (codex/provider.ts:1093), and whether that SDK surfaces steer is unchecked - node_modules is blocked by a hook. The aion report itself says 'assume not'.
