# Archon — Experience Spine: readable agent transcript

Paired with `DESIGN.md`.
This spine specifies the behavioural delta the transcript adds to two existing node rooms.
The machine contract — nine tool families, the four-tier resolver, elision rules, the todo fold, task normalization, occurrence grouping, the Raw toggle — lives in `../../../specs/spec-readable-agent-transcript/` and is cited, not restated.
Where this file disagrees with any mock, wireframe, or import, this file wins.

## Foundation

Web only.
shadcn/Radix on Tailwind v4, React 19.
Two surfaces render the same transcript:

| Surface                 | Route                                                  | Room                                                                  | Transcript component today            | Token source                    |
| ----------------------- | ------------------------------------------------------ | --------------------------------------------------------------------- | ------------------------------------- | ------------------------------- |
| Console (default route) | `/console/p/:projectId/r/:runId` (`ConsoleApp.tsx:87`) | `packages/web/src/experiments/console/components/ConsoleNodeRoom.tsx` | `inspect/ConsoleAgentHistoryList.tsx` | `experiments/console/theme.css` |
| Legacy                  | `/legacy/workflows/runs/:runId` (`App.tsx:98`+`:112`)  | `packages/web/src/components/workflows/NodeRoom.tsx`                  | `NodeTranscriptPane.tsx`              | `index.css`                     |

Both consume `buildAgentHistory()` in `packages/web/src/lib/agent-history.ts`, which gains the presentation and the folded todo state; both renderers add only markup.
Console must not import from `@/components/`, so the JSX is written twice, thin.
The room chrome around the transcript — rail, run header, toolbar, log stream, node panel on Console; run header, tabs, logs list, node panel on Legacy — is the shipped HITL contract and does not change.

Dark-only, because both token sources are dark-only.
Track A ships no schema, migration, or backend change, so the transcript improves every historical run the moment it deploys.

## Information Architecture

| Surface    | Reached from                                                                           | Holds                                                                                                           |
| ---------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Node panel | Click a node in Graph, a row in Logs, a node chip in Chat; the same panel on every tab | Header (type pill, node name, status badge, meta line, runs/iterations chips on Legacy) and the transcript body |
| Transcript | Panel body                                                                             | Occurrence groups in `seq` order; each group interleaves assistant text and tool rows                           |
| Tool row   | One per tool call                                                                      | Chevron, status glyph, family chip, headline, badges                                                            |
| Tool body  | Expand a row                                                                           | Body bar (facts left, Raw right) and the family's body arm                                                      |
| Raw        | Body bar button                                                                        | The exact provider JSON for that call                                                                           |

Nothing **in the transcript** is a route: which rows are open is local state and survives nothing. The panel around it is a different matter — node selection rides a `?node=<id>` query parameter (`console-run-href.ts:1-3`), so a node panel is deep-linkable even though the transcript inside it is not.
**The chips scope the transcript to one execution; they do not scroll.** The scoping happens in two places, and reading only one of them is misleading:

- **The server does the occurrence filter.** Selecting an occurrence puts `occurrenceId` and `attemptId` on the request (`lib/api.ts:717-719`), built from the `{kind:'occurrence', occurrenceId, attemptId?}` selection both rooms construct. The client then receives only that occurrence's messages. `selectNodeRoomMessages` returns them in `seq` order without cutting anything, and says why in its own comment: `// occurrence-scoped: server already filtered by occurrence_id/attempt_id`.
- **The client does the loop-iteration slice.** For `{kind:'loop_iteration'}` the same function cuts the list to the window between that iteration's `iteration_started` and its `iteration_completed` or `iteration_failed`.

**Both surfaces behave the same way.** Console calls the identical filter on its transcript (`ConsoleNodeRoom.tsx:603`); its own copy of the module lives at `experiments/console/components/inspect/select-node-room-messages.ts`. So the HITL README's "scoped to exactly that run" is accurate for both rooms and for both kinds of chip.

Neither room scrolls to a selection. The only scroll behaviour in either is Console's stick-to-bottom and its `scrollTop` restore (`ConsoleNodeRoom.tsx:550-572`).

→ Composition reference: `mockups/key-console-node-room.html` (Console chrome, running node, one failure auto-expanded), `mockups/key-legacy-node-room.html` (Legacy chrome, completed node, two occurrences), `mockups/key-transcript-states.html` (every family, hard case, glyph, header wording, and the open Raw toggle, surface-independent).

## Voice and Tone

Transcript microcopy is a machine reporting facts in lowercase, numbers first, `·` between facts.
It never congratulates, never explains, never wraps.

| Do                                                                                       | Don't                                                |
| ---------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `exit 0 · 38.9s`                                                                         | `Completed successfully in 38.9 seconds`             |
| `4 matches` · `11 files` · `418 lines` · `+2 −2` · `14 KB`                               | `Found 4 results!` · `Modified 2 lines`              |
| `2/5 done` · `3/6 done · 1 blocked`                                                      | `Progress: 40%`                                      |
| `1 subagent · 2m 04s` · `2 subagents`                                                    | `Spawned 2 agents`                                   |
| `running · 1m 48s`                                                                       | a spinner with no elapsed time                       |
| `Run 2 · retry` · `Run 1 · failed` · `Iteration 3`                                       | `Attempt 2` · `Pass 2` · `retry 1`                   |
| `todo updated` (folded row headline)                                                     | repeating the checklist                              |
| `folded from 5 todo calls` · `last call wins` · `batch · 2 subtasks` · `single dispatch` | body bars that describe the UI instead of the data   |
| `Raw` · `Raw ▾`                                                                          | `Show JSON` · `Debug`                                |
| `output missing` · `output unknown` · `truncated` — the existing markers, verbatim       | inventing new failure words                          |
| `—` when a row has no badge                                                              | an empty badge slot that shifts alignment            |
| The tool name exactly as the provider sent it: `read_file`, `Edit`, `Grep`, `eval`       | prettifying, title-casing, or translating tool names |
| `gitnexus · query` for `mcp__gitnexus__query`                                            | the raw `mcp__` string                               |

Assistant prose is the model's own words and is not edited.

## Interaction Primitives

Disclosure-first.
The transcript is read by scanning; opening is the exception.

- Click or tap anywhere on a row's summary toggles it.
- `Enter` / `Space` on a focused row toggles it.
- `Tab` moves through rows in document order; inside an open body the Raw button is the next stop.
- Raw is a button at the far right of the expanded body's first line, never on the collapsed row, so the collapsed row stays one scan-line.
- Failed rows open on first render; the reader may close them.
- **A reader's manual open or close outranks every automatic rule.** It persists across live re-renders while the node is running, and new rows arriving never reset it — including a row the transcript itself auto-opened because it failed. An explicit action by the reader is the strongest signal on the row, so nothing the stream does may undo it.
- Selecting another node swaps the panel content in place (room contract); open/closed state does not carry across nodes.

**Banned everywhere:** raw `JSON.stringify` as a default presentation; outcome carried by colour alone; hover-only information; a collapsed row taller than one line; a chip wider than 24 characters; the word `Attempt` anywhere in the transcript.

## Accessibility Floor

Behavioural. Contrast measurements are in `DESIGN.md` Colors.

- WCAG 2.2 AA is the target on both surfaces. The accessibility review re-measured every inherited pair independently and found the `--text-tertiary` shortfall wider than first recorded — Console failed as well as Legacy, and the hovered row was worse than the resting row on both. **Every transcript fact therefore sits in `--text-secondary` now**, which clears the floor on both surfaces; `--text-tertiary` is left with the chevron alone, which carries no fact and is hidden from assistive technology. What remains short is listed in `DESIGN.md` Open Questions rather than silently accepted.
- Outcome is decodable without colour: `✓ ✕ ◐ ⚠ –` are five different shapes; `+n` / `−m` carry their sign.
- Every row is a native `<details>`/`<summary>`, so it exposes `aria-expanded` and a button role without custom ARIA. Support varies by browser and screen-reader pairing, so **verify the expanded-state announcement on one Windows and one macOS pairing before the row is called done** — this is a risk to close during build, not a settled fact.
- **The row's accessible name is engineered, not emergent.** `<summary>` builds its name from every child, so left alone a row announces its chevron first, on all of hundreds of rows. Three rules fix it: the chevron takes `aria-hidden="true"` (it is decoration, and `<details>` already conveys the state it duplicates); the glyph character takes `aria-hidden` with a visually hidden name beside it; and the name order is **state → tool → target → facts**. `·` separators are decorative and must not be the only thing between two facts.
- **Row-to-row movement is `Tab`, and arrow keys do nothing.** That is the native contract: `Enter` and `Space` toggle the focused `<summary>`, `Tab` moves to the next one. Arrow keys would need custom JavaScript and a roving tabindex, which a list of independent disclosures does not earn — the pattern applies to a composite widget, and this is not one.
- **The status glyph carries an accessible name** (`succeeded`, `failed`, `running`, `interrupted`, `unknown`) in visually hidden text. This is a requirement, not a preference: `◐` is announced by some screen readers as a description of the shape, which is noise rather than status, and `–` is usually not spoken at all at default punctuation verbosity — so without the name, the unknown state announces as nothing.
- **The resolved family is available without colour, on three channels.** It travels in the chip's accessible name (`file · read_file`) for a screen reader; as the chip's `title` for a pointer reader; and as the first word of the body bar for anyone who opens the row. The third is the one that always works — it needs no hover and no assistive technology — which is why the family word in the body bar is a requirement and not a nicety. Colour remains the fast path, never the only path.
  This is the one deliberate exception to the hover-only ban below: the `title` **duplicates** what the body bar already states in text, so nothing is reachable by hover alone.
- **Scroll anchoring and focus during a live node.** The transcript pins to the bottom only while the reader is already at the bottom, and otherwise holds its position — the behaviour Console already ships (`ConsoleNodeRoom.tsx:568-572`). An append never moves focus. Both are cheap now and awkward to retrofit, because a failed row renders open and inserts a multi-line body into a single scroll container (`NodeRoom.tsx:142`).
- **A focused row cannot be hidden by the panel header as the room is built today**, so SC 2.4.11 is satisfied by the layout: `LegacyNodeRoom.tsx:250-253` renders the header and the body as _siblings_, and the `overflow-y-auto` scroller is inside the body (`NodeRoom.tsx:142`). The header's `sticky top-0` (`NodeRoomHeader.tsx:58`) therefore sticks to a container the transcript does not scroll within. This is a forward guard only: if the header is ever moved inside the transcript's scroller, the row summary needs `scroll-margin-top` equal to the header height.
- **The occurrence and iteration chips keep the semantics the shipped controls already have** — `NodeRoomHeader.tsx:64-76` is a native `<select aria-label="Execution">` and `NodeRunList.tsx:28-36` is a `<nav aria-label="Node runs">` of `<button>`s with `aria-current`. The states-sheet mock draws them as plain non-focusable `<span>`s; **the mock is wrong and the shipped markup wins**. Anyone building from the mock would turn a keyboard-reachable control into a pointer-only one.
- Focus is always visible: Legacy `{colors.focus-legacy}` 2px outline, offset −2px; Console `{colors.focus-console}` 2px outline, offset 2px.
- `Tab` order equals reading order; nothing is reachable by mouse only.
- The 120ms chevron rotation is disabled under `prefers-reduced-motion`. It is the transcript's only animation, so honouring the preference costs one media query.
- **New rows are announced narrowly, through one polite `role="status"` region, and not by blanketing the transcript in `aria-live`.** It announces node-level transitions and failures only — `"run_terminal_command failed, exit 101"`, `"implement node completed"` — and leaves individual successes silent, because announcing every row of a fifty-row streaming node is worse than announcing nothing.
  The earlier plan was to announce nothing and let the panel's status badge carry it. That fallback does not exist: the shipped badge is a plain `<span>` (`NodeRoomHeader.tsx:78`) with no `role="status"` and no `aria-live`, so it is not announced either. Without this region the one event the transcript exists to surface — a failure — is the one event a blind reader never hears.
- **Target size**: the Raw toggle carries `min-height: 24px`, grown by padding so its painted box is unchanged (SC 2.5.8). The tool row stays 22px — a deliberate, recorded 2px shortfall: rows stack with no gap so the spacing exception does not apply, but density is the feature and the surface is reached with a pointer. Revisit if it is ever targeted at touch.
- Text sizes stay at or above 10px, so browser zoom is the reader's remedy; the row does not reflow below that. Page zoom scales the panel and the text together, so nothing drops; only a raised root font size or text-only resizing puts the row under pressure, and then the body bar is what holds the dropped facts.

## Provider normalization at the edge

The transcript never learns a provider name.
Everything provider-specific is resolved in `packages/web/src/lib/` before a renderer sees it (`tool-presentation-contract.md`, Provider normalizers).
Reader-visible consequences:

- The chip shows the tool name as sent; the family colour is the only sign of resolution.
- A Codex name beginning with exactly `/bin/zsh -lc '` or `/bin/bash -lc '` has that prefix and the closing quote stripped for the headline; the script is never parsed; the full wrapped name stays in the terminal body and behind Raw.
- An MCP name renders as `server · tool`, following the backend formatter's convention.
- OMP's nine-op `todo` and Claude's whole-list `TodoWrite` produce the same checklist; OMP's batch `task` and Claude's single `Agent` produce the same subtask cards.
- `path` means the pattern in OMP `glob` and the search directory in Claude `Glob`; the headline is `pattern` when present, else `path`, and the reader never sees the difference.

## Occurrence grouping

Grouping keys on `occurrence_id`, never `attempt_id`.
A header appears only when a node has more than one group.

| Driver        | Header        | Suffix                                                                           |
| ------------- | ------------- | -------------------------------------------------------------------------------- |
| Retry epoch   | `Run N`       | `· retry` on a retried group, `· failed` on a group that failed, only when known |
| Loop ancestry | `Iteration N` | none                                                                             |

`Run` and `Iteration` match the panel header's existing runs/iterations vocabulary.
`Attempt` is forbidden because `attempt_id` is finer than an occurrence and the label would lie.
`Pass` was rejected for colliding with test pass/fail; reason-only labels were rejected for losing the ordinal.
Inside a group, assistant text and tool rows interleave in `seq` order.
Header options as rendered for the review: `mockups/key-transcript-states.html` §E.

## Elision and badge priority

A row is one line, so three things give way in a fixed order.

1. **Chip** caps at `{spacing.chip-max}` and ellipsises inside the pill.
2. **Headline** absorbs the remaining pressure: path kind elides in the middle so the filename survives; text kind elides at the end. The elision is **CSS on a two-span headline** — a head that may shrink and a tail that may not, per `DESIGN.md` Shapes — so it truncates the _rendering_ only. The full path stays in the DOM, which is what keeps it readable by assistive technology and selectable for copy. A produced string with characters cut out would destroy the path for every reader at once, and is not what this rule means.
3. **Badges** drop duration first; exit code, match count, file count, and `+n −m` are kept.

**Any badge dropped under pressure must still appear in the body bar.** The mocks already do this — the row badged `exit 101 · 41.2s` repeats `exit 101 · 41.2s · cwd …` inside its body — but it has to be a contract rather than a coincidence, because it is what turns "the duration badge drops" from information loss into one disclosure away. Dropping a fact with no path back to it would be a reflow failure at narrow widths.

Hard cases 1–4 in `mockups/key-transcript-states.html` §C show each rule under load.

## Inspiration & Anti-patterns

- **Lifted from `imports/superpowers-transcript-v2.html`:** density option B, the tool name as a chip, applied to the full transcript; middle elision, which keeps option C's one benefit without its double height.
- **Lifted from `imports/superpowers-transcript-v2.html` glyph option 1:** `✓ ✕ ◐` characters plus colour.
- **Lifted from the existing product:** native `<details>` disclosure; the `server · tool` MCP label; the room's `type-pill` radius for chips; the `runs` / `iterations` vocabulary of the panel header.
- **Rejected — density A** (`imports/superpowers-transcript-v1.html`): fixed-width tool-name column; long names are squeezed.
- **Rejected — density C**: two-line rows; twice the height for the same information.
- **Rejected — glyph 2**, a coloured dot: state in hue alone, lost to a colour-blind reader.
- **Rejected — glyph 3**, a left bar only on failure or running: also hue alone, and silent on success.
- **Rejected — neutral chips:** the user chose per-family colour at review, bound to existing `--node-*` tokens.
- **Rejected — nine chip hues:** they would outshout the status glyph; siblings share a hue.
- **Rejected — `Attempt`, `Pass`, and reason-only occurrence labels**, for the reasons in Occurrence grouping.
- **Rejected — GitHub-dark hexes** from both imports; every colour resolves to a product token.
