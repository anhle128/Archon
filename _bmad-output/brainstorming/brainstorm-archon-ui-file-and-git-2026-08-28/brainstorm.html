Job to Be Done

Người dùng "thuê" tính năng này để làm gì? Đào tận công việc thực sự cần hoàn thành, không phải để có thêm một cây file tree.

"Kiểm tra trạng thái file, xem những file nào hiện đang thay đổi, và nội dung của chúng ra sao."
Đối tượng được thuê: một radar worktree từ xa còn sống — dirty status + danh sách path đã đổi + nội dung file. Nó trả lời đúng một câu: "node này có đụng vào đúng thứ mình nghĩ nó đụng không?" — chứ không phải một IDE file tree chung chung.

Lấy VS Code làm hình mẫu, không phải bản clone

CoachTime-travel trên worktree từ xa: "bây giờ" (dirty status + content) đối chiếu với danh sách file của một commit trong quá khứ. VS Code SCM là hình dáng tham chiếu — không phải là một local clone.

04

SCAMPER

Sáu góc bẻ ý tưởng để tìm những khác biệt "chỉ có ở run-aware Source Control". Cả 5 ý được giữ — không cái nào lãng phí.

Combine
KEEPGhép Logs + Source Control: một dòng log chạy lệnh sẽ link tới các file lệnh đó đụng vào, nhảy thẳng đến diff của chúng.
Adapt
KEEPMượn từ workflow Graph: mỗi node hiện badge "changed-files"; click node để lọc Source Control về các file node đó tạo ra.
Put to
other use
KEEPTái dùng diff viewer làm bề mặt review HITL: cổng approval hiện đúng các diff của run trước khi approve.
Reverse
KEEPĐảo mặc định: mở Source Control ở các commit của chính run này trước, full history là bộ lọc dự phòng.
Eliminate
KEEPBỏ vùng Changes rỗng: run auto-commit no-HITL không có gì uncommitted → thu gọn Changes, dẫn đầu bằng history.

Batch bốn kỹ thuật hoàn tất: một thiết kế đã lắng + năm điểm khác biệt run-aware. User chọn chạy thêm một batch ý tưởng.

Failure Analysis

Ba cách tính năng này có thể vỡ. User: gạt failure #1 (secrets) sang một bên; với #2 & #3 hãy đọc code Archon thật + instance đang chạy, đừng đoán.

☰ Failure #1 · Rò rỉ bí mật — TẠM GÁC Diff viewer của file từ xa có thể lộ .env/secrets/keys sống trong worktree; cần redaction hoặc denylist trước khi hiện. → User quyết định set-aside lúc này.
⚠ Failure #2 · Repo/submodule mơ hồ Đây là workspace multi-repo có submodules → không rõ run đã dùng repo/worktree nào.
Trả lời (verified): Pin file reads vào run.working_path + codebase_id — đã lưu sẵn và expose tại GET /api/workflows/runs/{runId}. Một run bind ĐÚNG một codebase_id + một checkout working_path (nullable); submodules init --recursive vào worktree; project folder/--no-worktree có working_path null. WorkflowExecution.tsx:344 đã đọc workingPath.
⚠ Failure #3 · Worktree bị dọn/di chuyển Run xong, worktree bị cleanup hoặc move → file biến mất; viewer phải báo "worktree gone" chứ không crash.
Trả lời (verified): Worktree KHÔNG bị xóa ở terminal status; nó bị xóa bởi conversation/PR close, scheduler (merged 6h · stale 14d), thủ công, codebase delete, hoặc orphan. Destroy xóa checkout + git branch -D. Trước khi đọc: kiểm tra env active|destroyed + worktree còn tồn tại → hiện trạng thái "worktree gone". RUNTIME xác nhận run completed vẫn còn file.

Bằng chứng: CODE ⟂ RUNTIME

◧ CODE (đọc source thật)
  • Raw routes chỉ có: /api/stream/*, /api/artifacts/:runId/*, webhooks — không có route git/worktree/diff/source.
  • @archon/git chỉ có boolean hasUncommittedChanges (git status --porcelain).
  • Artifacts route resolve path server-side & reject .. (api.ts:5071-5078) — chính là hình mẫu cho một API git read-only MỚI.
  • isolation env status: active|destroyed (cleanup-service.ts, isolation/types.ts:28).
◨ RUNTIME (mac mini đang chạy)
  • Live API KHÔNG có route git/file/diff/worktree — chỉ /api/runs/{runId}/artifacts → feature này thực sự mới.
  • Run row lưu working_path (.../worktrees/archon/thread-<id>), output_root, codebase_id.
  • Cùng worktree xuất hiện dưới HAI root: /Users/agent/.archon/… vs 109 tool path dùng /Volumes/WD_BLACK/archon/… → path symlink/relocatable, UI phải realpath & chịu được cả hai.
  • Status enum: pending|running|completed|failed|cancelled|paused; run completed vẫn còn worktree.
UNVERIFIEDSự tồn tại của thư mục worktree trên mac mini chưa được stat (không có fs endpoint, không dùng SSH). DB working_path chỉ là bản ghi → UI phải xử lý thư mục biến mất ngay lúc đọc.

07

Crank the Dial to 11

Đẩy một thuộc tính lên cực đại để lộ ra đột phá.

11

Crank "remote-native" → 11

Tái dựng view file-đã-đổi của run từ event stream của workflow (event đã mang mọi tool_input file path + edit) → có change view kể cả khi git/worktree đã mất.

Đã hạ cấp: event stream KHÔNG authoritative cho changes — shell/sed/scripts/subprocess/rename/delete đổi file mà không sinh path event có cấu trúc → giáng xuống thành lớp phủ provenance tùy chọn.

Crank "speed + durability" → 11

Tại run-end / mỗi commit, precompute changed-files + diff rồi ghi làm artifact dưới output_root (sống sót qua cleanup). Source Control đọc artifact bền vững cực nhanh thay vì đụng worktree sống, chỉ fallback về worktree sống khi nó còn tồn tại.

Mô hình sự thật (Truth model)

Source of truth

git của worktree đang sống — nguồn thật cho changes/diff/history.

Durable post-cleanup

git-snapshot artifact do server sinh tại checkpoint (run end / per commit) dưới output_root.

Hint layer

events = gợi ý provenance (node/log nào có thể liên quan file), không bao giờ là change list.

Chiều diff cố địnhNOW = HEAD → worktree · commit đã chọn = parent → commit.

Tổng hợp cuối cùng

Sau vòng mirror, ba kết nối lớn khép lại toàn bộ phiên brainstorm.

1
Cái pin duy nhất: resolve working_path server-side từ runId + realpath — buộc chặt sự thật "1 run = 1 worktree" của user với luật bảo mật "không nhận path từ UI". Sai chỗ này thì mọi view đều sai hoặc mất an toàn.
2
Bề mặt đọc tối thiểu: git-from-worktree + diff-only + viewer M/A + manual Reload — vừa đủ để trả lời trọn vẹn JTBD "run này có đụng đúng thứ mình nghĩ không?".
3
Đáng tin trên run từ xa còn sống: trạng thái rỗng worktree-gone/null làm tính năng trung thực — thiết kế sớm ở Constraint Mapping, được bằng chứng lifecycle cleanup xác nhận đúng y nguyên về sau.

Top-3 ưu tiên v1

01
The Pin

Pin working_path

Server resolve working_path từ runId + realpath, reject .., read-only execFileAsync. Không bao giờ nhận path từ UI.

02
Read surface

git-from-worktree, diff-only M/A

git -C working_path log/show/diff/status. Click file → viewer: M = diff đỏ/xanh, A = single-pane content. File lớn + binary phải mở được.

03
Graceful

Worktree-gone empty state

Kiểm tra env active|destroyed + worktree tồn tại trước khi đọc; báo "worktree gone", không crash, không giả base repo.

★ Nâng cấp (SHOULD) — không critical cho v1

git-snapshot artifact bền vững dưới output_root

Artifact do server sinh tại checkpoint run-end. Đây là đột phá thật: nó biến "gone" thành "vẫn còn đây" và giải quyết slow + worktree-biến-mất + history bền vững cùng một lúc.
